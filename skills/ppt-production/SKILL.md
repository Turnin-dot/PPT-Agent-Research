# PPT 制作与交付决策指南

## 何时读取本 Skill

用户要求制作、修改、检查或导出演示文稿，或当前任务已有 slide plan、HTML、预览、评审或 PPTX 时读取。
只咨询论文内容且不涉及页面产物时，无需加载本 Skill；PDF 解析、核对和修复的细节读取
`pdf-asset-preparation`。

## 核心原则

- 先判断用户当前要整套交付、单页闭环、局部修改、只查看，还是阶段性草稿，再选择必要工具。
- 需求理解、论文理解、页面规划和 HTML 编写由主 Agent 完成；工具保存对象、读取证据、渲染、检查、
  评审和导出。不要为每次思考新增模型工具。
- 复用与当前对象版本一致的计划、HTML、预览和报告。修改 HTML、主题或引用后，旧报告与旧导出不能
  支持新版本。
- PDF 资产内部的图注和编号配对使用 PDF 修复工具；PPT 的 asset mapping 和 slide binding 只描述
  页面如何使用资产，不能改写上游证据。
- 路径只是引用。`inspect_image` 和 `review_slide` 会把真实图像送入模型；`get_asset` 只返回元数据，
  不能据此声称模型已看过图像。
- 检查成功但发现问题是有效报告，不是工具失败。未检查、无法判断、报告 stale 与 pass 分开解释。

## 按任务选择动作

### 新建整套论文汇报

读取或保存 brief，按需读取 PDF evidence/assets 和当前 theme。可以先保存 outline，再逐页细化；也可以
先完成最重要的一页再补其他页面。正式交付时每个必需页面应有当前 HTML、binding、实际预览、布局
报告和页面评审，再导出并验证 PPTX。不要把这段描述编码成运行时 DAG。

完整 PPT 交付不自动要求重新完成整篇 PDF 资产核对。已有 manifest 没有当前全量核对报告时，先检查
本次页面实际使用的资产、文字证据和来源版本；只有用户同时要求正式完成 PDF 资产准备、发现上游缺陷，
或当前页面结论无法由必要范围证据支持时，才读取 PDF Skill 并启动相应范围的核对。不要为了 PPT 验收
无故重跑已经完成过的整套 PDF 解析或全量视觉核对。

### 只制作或修改一页

读取 `get_task_state` 和该页当前计划/绑定。只更新相关 slide plan 或 HTML，保存新 binding 后重新渲染
和检查该页。其他页面没有版本变化时不要重做。整套 delivery 可以继续保持 `in_progress`。

### 已有资产与页面

优先使用稳定 ID 和精确版本。`get_evidence` 读取文本结论，`get_asset` 读取元数据，视觉判断才调用
`inspect_image`。需要更正 PDF 裁剪、OCR 或图注时回到 PDF Skill 的局部修复工具，随后更新受影响引用。

### 用户中途改变重点

更新 brief、outline 或相关 slide plan。已不需要的页面不必删除；交付时以当前必需 slide IDs 为准。
如果变更不影响某页内容、主题或引用，其当前报告可以继续使用。

## 页面制作：先决定信息怎样被看见

读取当前页的核心观点、必须保留的事实/数值/公式、关联资产及尺寸。先选一个主要视觉主体，
再分配解释、标签和来源的位置；不要直接把 main_points 的每一项包成一张卡片。
固定规划下可调整布局和精炼表达，不自行增删页面或改写关键事实。布局意图是内容组织的依据，
可读性冲突须说明，不能为了套版删除证据。

### 按页面类型选择布局

| 页面类型 | 首选组织方法 | 避免 |
|---|---|---|
| 网络架构 | 呈现真实网络结构时以原图或可溯源子图为主要证据；沿输入→主干→输出标少量解释，可上图下文或图文并列 | 整图缩成角落，以未经核实的自绘结构替代；要求原图占满整页 |
| 方法流程/模块 | 真实模块连接用原图定位；运算原理可用有来源的方向、尺度或输入输出示意，突出关键关系 | 为每句说明画同等大小卡片；把原理示意当作作者的实际网络结构 |
| 数学公式 | 一次强调一个关键关系，按原式展示，紧邻解释变量和作用；多式可按推导分组 | 把全部推导缩成小字；更改符号/上下标/运算来换空间 |
| 定量实验 | 先确定比较对象和指标，让主要差值与基线关系可读；必要时做经原表逐值核对的少量关键行视图，标来源及完整表位置 | 把多张十几行原表和大段结论一起缩放到不可读；混用百分比与百分点 |
| 定性对比 | 原图保持列序/标签/比例，优先给足横向空间；用1～2个确实可见的位置解释差异，区分作者结论与自身观察 | 罗列无法从当前尺寸看清的细节；裁掉GT、方法名或关键列 |
| 背景/结论 | 问题→不足→动机，或少量结论＋依据/局限；对照、因果或主次布局均可 | 所有内容机械三栏；重复标题、主张和正文同一句话 |

卡片仅适合真正平行、可独立比较的信息；顺序关系用流程，层级关系用主次大小。
优先0～3个主要内容区，不把数量当硬性上限；超过时重新检查是否需要精炼或报告过载。
通常只保留一层容器，不用卡片→卡片→标签多层边框制造层次。

### 字号、比例和实际展示尺度

以导出页面的物理尺寸为准，pt与CSS px不能混用。默认1600×900导出13.333×7.5英寸时，
字号pt≈CSS px×0.6；标题28～36pt约47～60px，正文18～24pt约30～40px，
辅助说明14～18pt约23～30px，来源/页码10～12pt约17～20px。其他尺寸按
`font_px × 72 × slide_height_inches / canvas_height_px` 换算。
这些是设计起点，不要求所有图内标签都达到正文字号；正文、辅助说明和来源必须有清晰层级。
`minimum_font_px=18`只是程序诊断阈值，绝不是正文合格线。不要用大标题掩盖主要内容很小。

先计算原图宽高比与可用区域的关系：保持比例，宽图优先通栏，竖图优先侧栏。
原图内文字不会因外围CSS字号增大而变大；需要增加图像显示面积、选择已有的清晰局部资产，
或用可读标签解释关键关系。查看原图后才判断细节，不把元数据或路径当作已经看过图片。
默认完整显示科学图、多子图和表格，不用cover或overflow截去边缘。局部展示须有明确范围、
来源与目的，并保留整图/上下文对应；缺少可溯源局部资产时不猜裁剪、不重绘科学内容。

先区分本页需要真实结构证据还是原理解释。方向性条带、不同K的感受野等可用自绘辅助示意，
与原文公式/定义核对并明确示意身份；不能添加无来源的模块连线、阶段对应或实验效果。
原图可只占上半部、下方解释配置；同一图可按不同目的复用。不要为了统一“用原图”而删掉有效的原理示意。
原图疑似不清晰时先核实实际展示与原PDF，不用统一像素长边阈值决定禁用或缩成参考图。
若计划仍有待重裁/待核验的必需资产，先按需使用现有PDF工具准备并更新引用；当前工具不可用时
报告具体缺口，不能用自绘替代来声称原图要求已满足。仅保存计划、列出asset_id或标记deferred不算准备完成。

### 空间与内容过载

完成主体布局后主动检查：若下半页或侧边仍大面积空白，而重要文字/图表仍偏小，优先扩大
主图、正文或比较数据区，重新分配区域；留白用于分组与引导，不用装饰去填满空白。
卡片内文字留足内边距，不能压住彩条；图注贴近对应图但不能碰到表格最后一行。

内容放不下时按顺序处理：删重复措辞→短句/关键词替代长句→把辅助推导移入已有讲解提纲→
调整空间和分组。保持核心事实、关键数值/公式、所需图表和来源不变，不能持续缩小主要文字。
原表必须完整展示但现场无法读清时，保留原表及关键结果的清晰解释，并明确限制；不要假装小图可读。
仍无法满足时，用现有文件工具保存`planning_overload.json`，至少包括当前slide_id、无法兼顾的
必需内容、已经尝试的精炼/布局方法、具体拆页建议和应保留的证据ID。继续保存可复查的当前HTML
和绑定；报告过载，不自动拆页、不默默删除核心内容。不能仅因规划标了high就不做布局判断。

### 首次保存前自查

检查主要观点是否一眼可见、主图是否完整且足够大、正文是否真能用于投影、图注/来源是否对应，
以及是否有“小字＋大空白”、重复文字、伪层级或无必要的卡片。完整证据表与口头讲解的角色应区分。
有实际预览时查看截图和诊断，而不是只读HTML；首次生成与后续审核修订的结果分别记录。

## 工具职责

| 工具 | 何时使用 | 副作用与重点结果 |
|---|---|---|
| `get_task_state` | 继续任务、局部修改、交付前 | 只读；关注 task revision、对象版本与 completion state |
| `get_paper_context` | 从已准备论文开始理解与规划，或读取未加载资料段 | 程序整理原始资料，无模型总结；关注分段、覆盖与缺失，复用首轮已投递内容 |
| `get_evidence` | 按 ID、页或关键词取原文证据 | 只读、有界摘录；不是整篇自动总结 |
| `get_asset` | 定位资产路径、类型、版本、来源页 | 只读；路径不等于视觉检查 |
| `get_theme` | 编写 HTML 或检查主题一致性前 | 只读；未保存时会返回明确标记的默认主题 |
| `inspect_image` | 理解源图像或按需核实关键表格单元格 | 调用配置的独立视觉模型；table_cells保存版本化派生证据，原图及原HTML保持只读 |
| `save_brief` / `save_theme` | 保存当前需求与主题 | 写入版本；相同内容幂等，旧 task revision 被拒绝 |
| `save_outline` | 保存整套叙事结构 | 写入版本；不要求所有页面同时完成 |
| `save_slide_plan` | 保存一页目标、Markdown 与引用 | 写入版本；校验 asset/evidence/theme 版本 |
| `save_asset_mapping` | 记录 PPT 中的资产别名、用途 | 写入 PPT 状态；不改变 PDF 内部配对 |
| `save_slide_binding` | 保存 HTML 版本和元素来源绑定 | 复制 HTML、校验元素 ID；旧预览/评审/导出失效 |
| `render_html_slide` | 需要真实 HTML 预览 | Chromium 渲染 PNG + DOM/资源诊断；不代表通过 |
| `inspect_html_layout` | 检查溢出、越界、资源、遮挡和字号 | 程序报告绑定 HTML 版本 |
| `review_slide` | 需要事实、图文、视觉与主题评审 | 豆包读取真实预览和绑定证据；报告只读 |
| `export_editable_pptx` | 当前页面达到交付条件 | 生成独立文字、图片、形状对象及对象映射；记录降级 |
| `render_pptx` | 检查实际 PowerPoint 输出 | Microsoft PowerPoint 实际打开并导出 PNG |
| `validate_export` | 验证可编辑性与渲染差异 | 程序检查 OOXML/对象，并由豆包分批对照 HTML 与 PowerPoint 渲染 |
| `validate_delivery` | 正式声明当前范围完成前 | 汇总当前版本和报告；不满足时保持 in_progress |

详细的 HTML 可编辑导出约束按需读取 `references/html-export-contract.md`。
PDF 字段、目录查询、证据续读和结构化结果引用的使用约定按需读取 `references/pdf-asset-reading.md`。

## 结果解释和恢复

### 双维审核与定向修订

`review_slide(scope="all")`分别保存Qwen内容忠实度和豆包视觉报告；可用`content`或`visual`只补查一维。
必须分别读取两维报告及程序诊断，不以视觉高分抵销事实错误。问题按页面、element_id/位置、类型、
严重性、可观察证据和建议定位。重要事实错误、严重裁剪/遮挡、黑屏或资源缺失阻断交付。
仅修改确有问题的元素和必要的相邻空间；先列出须保持的正确公式、数值、资产、引用和区域。
视觉调整不得改写事实或自行删减核心内容。公式修订须对照来源逐项保留操作顺序、变量和上下标。
修订后保存新binding、实际渲染、程序检查，并分别复核内容和视觉；旧版本通过不支持新版本。
按原问题逐条比较“实际变了什么、问题是否消除、是否引入回退”，不能用总分上涨代替效果验证。
默认一次定向修订；仍有问题明确列出未解决项，停止无效循环，不为提高分数重复审核。
证据不足使用uncertain，报告规划过载而非私自拆页。两维均当前通过且技术检查通过才正式交付。

- 参数或版本冲突：调用 `get_task_state`/`get_asset` 读取当前值，重新应用用户意图；不要原样覆盖。
- 无效引用：修正具体 ID、manifest 或版本。不要虚构资产，也不要仅删除引用来掩盖证据缺口。
- 浏览器资源失败：修正本地资源路径、字体或 HTML，再保存新 binding；不能把无报错等同布局合格。
- 页面 `needs_revision`：按元素 ID 和建议修改 HTML/计划/资产，保存新版本后重新渲染与评审。
- 页面 `uncertain`：补充证据或原页；无法判断时保留不确定性。
- 导出降级：根据对象映射与 unsupported features 简化 HTML/CSS 或接受并明确记录限制。
- PowerPoint 无法打开/渲染：保留 HTML、PPTX 和对象映射，报告运行环境阻塞；不能把文件存在当通过。
- 多次修订仍无法满足：保留当前草稿和正确页面，列出未解决问题，不误报 delivery complete。

## 完成判断

局部请求完成，只要求当前范围的版本、预览和必要检查一致。完整交付还需必需页面报告为 current、PPTX
含可编辑对象、实际 PowerPoint 渲染可用、导出验证通过，并由 `validate_delivery` 对当前 task revision
给出 `pass`。结束当前回答不等于任务完成。
